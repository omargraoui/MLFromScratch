# Local verification

The acceptance checks were executed on Windows with Python 3.13.5, NumPy 2.5.3 and
scikit-learn 1.9.0. Dependencies were installed in an isolated temporary environment
outside the repository. The package author and MIT copyright holder are Omar Graoui.

## Tests

```bash
python -m pytest --cov=ml_from_scratch --cov-report=term-missing --cov-report=xml
```

Result: **241 passed**, **98.41% branch-inclusive coverage**. The configured minimum is
90%. The suite includes numerical gradients, independent reference comparisons, invalid
inputs, overflow, reproducibility, failed refits and the runtime dependency boundary.
Logistic gradient checks also use an independent high-precision decimal reference at
logit magnitudes up to 1000 and verify convergence symmetry under label inversion.

## Benchmarks and figures

```bash
python -m benchmarks.run_all --update-readme
python scripts/generate_figures.py
```

Results: **43 metric comparisons**, **10 paired model runs**, **six unique datasets**,
and **five generated figures**. CSV, JSON and Markdown outputs are under
[`benchmarks/results`](../benchmarks/results). All iterative benchmark fits converged.
Numerical results are generated by executing the estimators; runtimes and timestamps vary.

## Code quality and executable documentation

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pip check
python scripts/verify_artifacts.py --notebooks --write-notebooks
```

Ruff lint and formatting pass, mypy reports no issues in 17 runtime source files, and pip
reports no broken requirements. All five independent README examples pass. Local Markdown
file links resolve, and CI YAML syntax, triggers and job/step structure validate.
All five notebooks execute sequentially in fresh kernels, with real outputs saved in the
repository (about 420 KB combined). The temporary kernel specification uses the active
interpreter; notebooks themselves retain portable `python3` metadata.

The wheel and source distribution were built with `python -m build` using its isolated
build backend. Generated build archives and the local virtual environment are kept outside
the repository. The source distribution includes experiments, documentation and notebooks;
the wheel contains the runtime package and its MIT license.

A second clean environment installed the built wheel and NumPy only. All five README examples
passed there while executing outside the repository; scikit-learn was absent. Installed
package metadata reported **Omar Graoui** as author. CSV/JSON values and the generated README
table were also cross-checked for consistency.

## Engineering review

Final review led to explicit linear-prediction overflow handling, an L2-free path that avoids
unnecessary squaring of large coefficients, atomic publication of K-Means fitted state, and
two-part PCA centering for large offsets. Regression tests cover each of these behaviors.
The source-distribution manifest includes the educational artifacts, and README results
refresh from generated measurements through the benchmark command.

The repository makes the implementation, mathematics and evidence easy to find. Its remaining
portfolio limitations are the familiar algorithm selection, one fixed benchmark split, and
the absence of external usage or review. Strong next steps would be repeated-split uncertainty
estimates and a focused study of conditioning and learning-rate selection.

## Scope of the evidence

These are local results, not a claim that hosted GitHub Actions has already run. The workflow
targets Linux on Python 3.11 and 3.13. A remote repository is not required for the local
installation, tests, benchmarks, figures or educational examples.
